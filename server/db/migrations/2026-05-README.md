# Padel DB — May 2026 performance & integrity migrations

Five small, idempotent migrations. Run them **one by one** in phpMyAdmin
on `u502561206_padel_db` (production) and `padel_db` (local XAMPP).

All scripts are **safe**:
- Pure `ADD INDEX` / `ADD COLUMN` — no data changes
- Idempotent via `INFORMATION_SCHEMA` guards (re-running does nothing)
- Final `SELECT '...' AS status` to confirm success
- No DROP, no RENAME, no FOREIGN KEY — zero risk of breaking existing app

## Why these specifically

- The audit found heavy WHERE/JOIN patterns on `(club_id, court_id, date)` and
  `(member_id, status, date)` with no covering index → these are the queries
  that get slow first as data grows.
- Financial tables (`booking_payment_shares`, `booking_refunds`, wallet ledger)
  had **no soft-delete** — accidental deletes would be unrecoverable. Now
  rows are marked, never destroyed.

## What's NOT here (and why)

- No FK constraints — current data likely has orphan rows; adding FKs would
  fail. That's a separate cleanup project.
- No TIME-type conversion for `start_time`/`end_time` — touches every booking
  insert/update path; needs JS-side change too.
- No partitioning on `club_bookings`/`audit_log` — needs MySQL 8 partitioned
  storage and downtime.
- No FK on `app_store` / `entities` JSON blobs — deprecated path, will be
  removed in a future migration.

## Verifying after run

```sql
-- Verify new indexes exist
SELECT table_name, index_name
FROM information_schema.statistics
WHERE table_schema = DATABASE()
  AND index_name LIKE 'idx_%'
ORDER BY table_name, index_name;

-- Verify soft-delete columns exist
SELECT table_name, column_name
FROM information_schema.columns
WHERE table_schema = DATABASE()
  AND column_name IN ('deleted_at', 'deleted_by')
  AND table_name IN ('booking_payment_shares', 'booking_refunds', 'member_wallet_ledger');
```

## Rollback (if needed)

```sql
-- Remove an index
ALTER TABLE club_bookings DROP INDEX idx_cb_club_court_date;

-- Remove a soft-delete column
ALTER TABLE booking_payment_shares DROP COLUMN deleted_at, DROP COLUMN deleted_by;
```

Always test on local XAMPP first.
